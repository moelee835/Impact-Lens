# 팀 협업 역할별 문서화 규칙

## 목적과 사용자 가치

- **누가 어떤 문제를 겪는가:** 이 저장소의 소유자(사용자)는 여러 개의 Claude Code 세션(lead,
  coder, reviewer, tester)을 동시에 열어 협업으로 작업을 진행한다. 그런데 지금은 "누가 무엇을 왜
  하기로 했는지"와 "그 세션이 실제로 무엇을 했고 무엇을 검증했는지"가 각 세션의 대화창에만 흩어져
  있어, 나중에 결과를 재구성하거나 신뢰하기 어렵다.
- **끝나면 무엇이 가능해지는가:** lead가 teammate에게 작업을 넘기기 전에 그 작업의 목적·산출물·검증을
  먼저 기록하고, teammate는 작업을 수행한 뒤 실제로 무엇을 바꾸고 어떻게 검증했는지 남기게 된다.
  그 결과 사용자는 대화 로그를 뒤지지 않고도 "이 변경이 왜 지시됐고, 정말로 검증됐는가"를 문서만으로
  확인할 수 있다.
- **상위 목표와의 관계:** 이 규칙은 사용자가 새로 구성한 lead↔coder/reviewer/tester 협업 체계가
  AGENTS.md의 목적 중심·검증 우선 원칙을 세션 경계를 넘어서도 지키게 하는 안전망이다. 이 안전망이
  없으면, 여러 세션이 병렬로 움직일 때 "구두로 지시하고 구두로 완료 보고"하는 검증 공백이 생긴다.
- **왜 지금인가:** 사용자가 tester 세션을 추가하고 cmux로 세션 간 작업 지시를 시작한 시점이다.
  실제 작업(M3 사용자 테스트 등)을 teammate에게 배정하기 **전에** 이 규칙을 먼저 세워, 첫 배정부터
  규칙이 적용되도록 한다.

## 배경과 해결할 문제

- 현재 agent teams(`CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`)는 세션마다 독립된 단일 멤버 팀으로
  동작한다. coder/reviewer/tester는 각각 별개 세션이며, 공유 task list나 메시지 버스로 묶이지 않는다.
- 사용자는 이 세션들을 cmux(`cmux send` / `cmux send-key`)로 lead가 구동하는 방식으로 협업하기로
  결정했다. 이 방식에서는 조율과 기록이 전적으로 lead의 규율에 달려 있어, 문서화 규칙이 명시되지
  않으면 검증 근거가 남지 않을 위험이 크다.
- AGENTS.md는 "한 세션이 한 작업을 수행"하는 관점에서 작성돼 있어, **세션 간 지시·보고**에 대한
  명시적 규칙이 없다. 이 공백을 메운다.

## 범위와 범위에서 제외할 항목

- **범위:** AGENTS.md에 "팀 협업과 역할별 문서화 규칙" 절을 추가한다. 규칙은 (1) lead가 지시 전
  기록할 것, (2) coder/tester가 작업 후 기록할 것, (3) reviewer가 검토 후 기록할 것을 정의한다.
- **제외:** cmux 구동 명령의 자동화 스크립트화, agent teams 재구성, teammate 세션의 설정 변경은
  이 작업에 포함하지 않는다. 실제 M3 사용자 테스트 수행도 별도 작업으로 분리한다.

## 현재 구현 조사 결과

- 이미 달성된 것: AGENTS.md §0~§6이 단일 세션 기준의 목적 설명, branch 분리, 사전 작업 문서, 작업
  로그, 검증, 단계별 commit/push, 완료 보고를 규정한다. CLAUDE.md는 Claude Code가 목적 중심 계획·보고를
  놓치지 않도록 강조한다.
- 아직 불가능한 것: 여러 세션이 협업할 때 "지시 전/작업 후" 문서화 책임이 어느 역할에 있는지 규정이
  없다. 이번 작업이 이 공백을 메운다.
- 근거: `~/.claude/teams/session-*/config.json`이 각 세션을 단일 멤버(team-lead) 팀으로 보여준다.
  cmux `send`/`send-key`로 세션 간 프롬프트 주입이 가능함을 handshake로 확인했다(coder 왕복 ~3초).

- **목적:** lead↔teammate 협업에서 지시·보고의 문서화 책임을 명문화해 검증 공백을 없앤다.
- **산출물:** AGENTS.md에 "## 7. 팀 협업과 역할별 문서화 규칙" 절이 추가된다. lead의 지시 전
  기록 의무, teammate의 작업 후 기록 의무, reviewer의 검토 후 기록 의무가 기존 §2(사전 작업 문서)와
  §3(작업 로그) 형식을 재사용해 정의된다.
- **검증:** AGENTS.md가 새 절을 포함하고, 기존 절 번호·참조와 충돌하지 않는다. 규칙이 기존
  §2/§3 형식을 그대로 가리키는지 문서 내 상호 참조로 확인한다.
